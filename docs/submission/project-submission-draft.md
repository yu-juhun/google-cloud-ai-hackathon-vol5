## プロジェクト概要

車椅子ユーザー向けバリアフリー旅行プランニングエージェント「michibiki」。声で話すだけでAIがあなたの移動条件や好みを引き継いだ「仮想の自分」たちを作り、あなたよりひと足先に旅先を巡ってもらいます。Google Places APIの情報とレビュー・写真をGeminiで解析して、個人条件に照らした「実際に入れるか」を理由付きで判定、一日の旅程を提案します。ユーザー専用のアバターを生成して仮想の自分に反映し、体験写真もアバター本人として個人化。完成した旅程はVeoで動画化し、出発前に体験を疑似的に味わうこともできます。

仮想の自分は、あなたの条件を引き継いだ「もうひとりの自分」。あなたよりひと足先に旅先を巡り、その一日をレポートにしてあなたに届ける。michibikiは、そんな新しい旅の選び方を提案します。

## 課題と解決

**課題**

車いすでの旅行では、行き先をその場で変えるのは簡単ではありません。楽しみにしていた店まで移動した後で「入口を通れない」と分かっても、すぐに別の場所へ向かえるとは限らないです。そのため行き先を探す段階から、自分が利用できるか、入れるかをできる限り確かめる必要があります。

一方で、店舗に「バリアフリー対応」と書かれていても、自分の車いすの幅で入口を通れるか、越えられない段差がないかまでは分かりません。段差・通路幅・多目的トイレの有無などを知るには、施設ごとにWeb検索をして、公式情報やレビュー、写真をたどる必要があります。

一か所を調べて終わりではありません。行きたい場所の候補をいくつも調べ、その中から自分の条件に合う場所を選び、一日の予定としてつなげる。旅を一回計画するだけで、この作業を何度も繰り返すことになり負担が大きいです。

その上、Web検索には自分の車いすの幅や段差の条件(パーソナライズされた情報)、旅でやりたいことが最初から入っているわけではありません。検索結果を自分の条件と行きたい場所に照らし合わせ、旅程にするのは自分です。以上のように、車椅子ユーザーが旅行を計画するのは多くの負担がかかっています。

**解決アプローチ**

- **声で条件と希望を伝える**:Gemini Liveとの音声対話から、移動制約・食事制約・目的・同行者などをAIが自分で質問しながら聞き出し、各属性に優先順位(rank)と確からしさ(confidence)を付けて構造化。低確信度の内容は条件として採用しない
- **仮想の自分エージェントが行き先を調べる**:本人の条件と希望を引き継いで候補地を探す。裏側では検索→判定→推薦の3つの専門エージェントが役割を分担し、Google Places APIの施設情報に、レビューや写真、Web検索で見つけた施設の公式案内などを重ねて調査する
- **パーソナライズされた旅先検索**:本人の移動条件と行きたいことを引き継いで候補地を探し、施設の設備情報や公開情報を照らし合わせる。入口幅・段差の数値が確認できた場合は本人の条件と比較し、判断できない点は「要確認」として理由付きで提示
- YouCam AI Avatarで生成した本人専用のアバターを仮想の自分に個人化し、体験レポート画像にも反映(衣装やアートスタイルではなく顔・髪型のみを継承するようプロンプトを調整)
- **旅全体を動画でも見られるようにする**:完成した旅程をもとに、複数の訪問先で過ごす場面をVeoで動画化する。出発前に、その旅の一日をイメージできるようにする
- **スマホでの利用を考えた待ち時間の設計**:旅の分析処理は非同期化し、クライアントはポーリングで結果を取得。低速回線や接続断でも結果を取りこぼさない設計に

## アーキテクチャ説明

**構成**

- フロントエンド: React (Vite) on Cloud Run
- backend-api: FastAPI on Cloud Run。Cloud SQL (PostgreSQL) で依頼・プロフィール・アバター・動画ジョブを永続化
- 検索・判定・推薦の3エージェント + trip-orchestratorをそれぞれ独立したCloud Runサービスとして分離
- persona-agent-backend: Gemini Liveでの音声聞き取り・ペルソナ抽出・YouCam AI Avatar生成を担当する、DBアクセスを持たないステートレスな実行専用サービス
- video-agent: Veoで旅程全体の動画を生成

**利用AI技術**

Gemini(店舗のバリアフリー判定・推薦理由生成・体験写真生成・音声対話からのペルソナ抽出)、Gemini Live(音声での旅の相談)、Veo(旅程動画生成)、YouCam AI Avatar(ユーザー専用アバター生成)

### AIエージェントによる調査・判定の工夫

#### 一度の依頼で最大10体のエージェントを動かす

より多くの仮想の自分エージェントが旅先を調べれば、その分だけ訪問先や過ごし方の候補が増え、生成される体験レポートにも厚みを持たせられます。そこで、一度の依頼で最大10体のエージェントを動かせる構成にしました。

とはいえ、人数を増やすだけでは全員が似た場所を調べてしまいます。ユーザーの依頼は自然な言葉で書かれ、行きたい場所や楽しみたいことも旅ごとに違います。複数のエージェントを生かすには、依頼を解釈して「誰が何を調べるか」を毎回決める必要がありました。

そこで、調査を振り分ける**親エージェント**を置きました。親エージェントは依頼と事前登録された移動条件を読み取り、指定された人数に応じて調査の担当と検索内容を動的に決めます。たとえば、美術館の候補、駅や入口からのアクセス、休憩できるカフェといった役割を、その旅に合わせて子エージェントに割り当てます。

結果として、役割が明確になり子エージェントはそれぞれの担当を掘り下げながら、候補検索を並列に進められます。一体だけで広く浅く調べるのではなく、複数の視点から集めた情報と仮想体験を、最後に一つの旅程へまとめられるようにしました。

```text
旅の希望 ＋ 登録済みの移動条件
                 ↓
親エージェント：希望を解釈し、人数分の担当を決める
        ├─ 仮想の自分① 美術館の候補を調べる
        ├─ 仮想の自分② 駅からのアクセスを調べる
        └─ 仮想の自分③ 休憩できるカフェを調べる
                 ↓
調査結果を集約 → 一日の旅程と体験レポート
```

#### 「通れるか」に銀の弾丸はない。公開情報を複数の視点で掛け算する

どの施設でも「この人は通れる」と一発で分かる情報源はありません。Google Placesに「車いす対応入口あり」と載っていても、幅70cmの車いすが通れるかまでは分からないためです。そこで、施設ごとに次の観点で集めた情報を掛け算する方式を採用しました。

| 観点 | 具体的に探す情報 | 旅程に必要な理由 |
| --- | --- | --- |
| 施設の対応設備 | Google Placesの車いす対応入口・トイレ・座席・駐車場 | 候補を探す手がかりにする |
| 入口の条件 | 公式案内にある入口の有効幅、段差、スロープ、エレベーター、画像 | 本人の車いす幅や越えられる段差と比べる |
| 駅からのアクセス | 交通事業者が公開する出口、エレベーター経路、車いす対応トイレ | 施設の中だけでなく、着くまでの経路も考える |
| 訪問中の設備 | トイレ、座って休める場所 | 滞在中に休憩できるかを考える |
| 一日の予定 | 営業時間、続けて移動できる時間 | 無理のない順番と休憩を組み込む |

一つの情報だけを見て「通れる」と決めることはできません。エージェントが候補地ごとにこれらの手がかりを探し、設備の有無だけでなく、入口からの動線、休憩のしやすさ、一日の移動まで本人の条件に照らしていきます。

決定的な情報がないからこそ、別々の公開情報を突き合わせ、掛け算して判断の確からしさを高める。地道な方法ですが、この積み重ね方式で一人ひとりに合う旅程を作っています。

#### AIの判断を、出典までたどれる形で返す

AIには、もっともらしい誤り(ハルシネーション)があります。公開情報を調べても、現地で本当に利用できるかを100%保証することは難しい印象です。入口幅や段差のように、間違えると旅先での行動に直結する情報だからこそ、AIの答えだけで言い切らない設計にしました。

確認できた事実、公開情報からの推論、分からないことを分けて扱います。入口幅や段差の数値は、出典に同じ施設名・数値・単位が記載されている場合だけ本人の条件と比較し、根拠が足りなければ「要確認」とします。

レポートには参照元へのリンクも載せています。「本当かな」と感じたときに元の情報へすぐ戻り、施設案内や、掲載されていれば写真も自分の目で確かめられるようにするためです。AIの判断をそのまま信じてもらうのではなく、本人が納得して判断できる材料を残しています。

### アバター・音声・利用体験の工夫

- アバター生成はYouCamの71スタイルから重複なしでランダム10種を選出し、使い切ったら削除して再抽選(v2)する方式で、毎回同じ見た目にならないようにした
- 各仮想の自分の体験写真に本人のアバターを反映する際、Geminiには顔・髪型のみを参照させ、アバターの衣装やファンタジー調のアートスタイルを引き継がないようプロンプトで明示的に制御
- 音声対話から抽出した属性のうち、**外見に反映してよい項目を「移動制約」のみに明示的に限定**(許可リスト方式)。宗教・出身地・国籍などの属性がアバターの見た目に紛れ込み、AIが勝手にステレオタイプな外見を生成するリスクを設計段階で遮断している
- 旅の分析はPOST直後に即時応答し、実処理はバックグラウンドで継続、フロントはポーリングで結果取得。長時間接続に依存しないため、ブラウザやネットワーク環境を問わず安定動作する

## 動作確認の方法

1. デプロイURLにアクセス(認証不要・個人情報の入力不要。ブラウザごとのランダムトークンで識別されます)
2. 「あなたの条件」画面で出発地・車椅子条件を確認(初期値のままでも動作します)
3. 「旅をつくる」から行き先・日時・してみたいことを入力して送信(「声で相談する」を選ぶと、Gemini Liveとの音声対話で条件・希望を伝えられます)
4. 1〜2分ほどで仮想の自分たちが調べた結果・体験レポートが表示されます
5. (任意)プロフィール画面で写真をアップロードするとご自身のアバターを生成でき、スタイルの性別フィルタも選択できます
6. (任意)完成した旅程から動画生成を試すこともできます
